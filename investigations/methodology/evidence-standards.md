# Evidence Standards

IDMON investigations separate deterministic blockchain evidence from stored system labels, observed structures, interpretation and unresolved questions.

## Evidence classes

### `ON_CHAIN_FACT`

Deterministic blockchain data reproduced from local Bitcoin Core and, where applicable, corroborated by IDMON's stored record.

### `IDMON_EXISTING_LABEL`

A classification, signal or profile tag already stored by IDMON. It is not independent proof of attribution or intent.

### `OBSERVED_PATTERN`

A descriptive pattern formed from confirmed transactions without asserting ownership, purpose or identity.

### `HEURISTIC_INFERENCE`

An interpretation compatible with the evidence but not proved by it.

### `UNRESOLVED`

A question the available evidence cannot answer.

## Investigation principles

- Evidence before narrative.
- Use exact transaction and outpoint references where available.
- State evidence provenance explicitly.
- Make calculations reproducible.
- Preserve plausible alternative explanations.
- Require independent evidence for attribution.
- Movement does not equal sale.
- Keep uncertainty visible.
